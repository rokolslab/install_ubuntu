# Supabase Studio healthcheck used unreachable loopback

**Date:** 2026-07-15 01:19
**Files:** docker-compose/docker-compose.yml
**Severity:** high

## Problem

`supabase_studio` was `running` but Docker reported `unhealthy`. The inherited image healthcheck failed with `ECONNREFUSED 127.0.0.1:3000`, while the host-level check `http://127.0.0.1:54323` succeeded.

## Root Cause

The Supabase Studio image healthcheck assumed the app was reachable through `localhost` inside the container. On the tested Docker network, Studio was reachable through the service DNS name `supabase_studio:3000`, not container loopback.

## Solution

The Compose service now overrides the image healthcheck and checks the same `/api/platform/profile` endpoint through `http://supabase_studio:3000`. This keeps the check at the application HTTP layer instead of weakening it to a process-only probe.

## Prevention

- When image healthchecks fail but published host ports work, verify loopback, container IP, and service DNS separately from inside the container.
- Prefer application endpoint checks over process checks for readiness.
- Run `docker inspect .State.Health` after image tag changes and Compose overrides.
